# services

- `services/Éditer les métadonnées.workflow` is Michael's own Finder Quick Action for metmux (his choice 2026-10-19): the repo `/Users/michael/Developer/metmux` is only read (its `metmux.py` runs), never modified, and the workflow published with metmux is never used. It is installed as a symlink by `services/sync.sh` (macOS follows it, tested by Michael 2026-10-19). If metmux changes its command line (`--mode=ask`, arguments), update the copy here: it does not follow the repo. The repo's own `local/regen_quickaction.py` is obsolete for this; never use it. The workflow has no icon (no `NSIconName`/background keys in `Info.plist`, no `systemImageName`/`backgroundColorName` in `document.wflow`), meant to make Finder list it directly at the bottom of the right-click menu like OCR sur PDF instead of under Actions rapides (Michael's request 2026-10-19, not yet tested on the Mac); re-saving it from Automator with an image would send it back there.
- `services/Créer un PDF.workflow` (rewritten from a blank page 2026-10-24, on Michael's decisions): merges the selected PDFs and images in click order into one PDF next to the first file, named like Apple (`doc1 2.pdf`), originals untouched. The bash part only checks the Homebrew tools (img2pdf, qpdf, exiftool, and mozjpeg, keg-only so called as `/opt/homebrew/opt/mozjpeg/bin/cjpeg`, all installed by `services/sync.sh`), then runs a Python heredoc in img2pdf's own Python, which carries img2pdf, Pillow and pikepdf. PDF pages: qpdf `--stream-data=preserve`, byte for byte; attachments, layers and signatures raise a "garde l'original" alert; a qpdf repair raises an alert naming the file, except when its only warnings are empty index slots ("object has offset 0", written by macOS itself) that no `N G R` reference in the raw file or its object streams points to (Michael's macOS scan, 2026-10-25; qpdf 12 ends that warning with " - a common error...", so never anchor it at line end, 2026-10-26); bookmarks, title, author, subject or keywords, XMP metadata, accessibility tags (/StructTreeRoot), document language (/Lang) and named destinations (/Dests, /Names /Dests) are dropped by the merge and raise one simple alert (Michael 2026-10-27, since he deletes the originals after merging), one line per lost item naming three files and counting the rest, placed after the serious notes so a hundred titled PDFs cannot bury a "garde l'original", so most PDFs not made by a macOS scan alert; /PageLayout, /PageMode and /ViewerPreferences go silently. Images: JPEG, PNG, GIF, BMP, WebP and `.tif` go to img2pdf as they are, anything else (HEIC, AVIF, RAW) is first decoded by `sips` to PNG, then turned upright and stored by mozjpeg as a JPEG of quality 88 with 4:2:0 chroma and its color profile (Michael 2026-10-27: about as heavy as the HEIC, a fixed setting, "déterministe"; 2.09 Mo for his 2.12 Mo photo at 41 dB, where Pillow's libjpeg-turbo needs 2.45 Mo for the same fidelity; Homebrew builds jpeg-xl without jpegli and guetzli is deprecated, so mozjpeg is the best encoder it offers; refused only below 20 dB against the decoded photo, i.e. a failed conversion, since pure noise measures 28 dB; only HEIC with transparency stays lossless PNG); every image page is then compared with its source (JPEG and 16-bit PNG byte for byte, the rest pixel for pixel, upright, same color profile); on a mismatch a second way decodes, turns upright and stores the pixels as PNG, checked again; still different = refused. Rare formats get no special handling, the check refuses them (Michael's principle: no needless defensive code, say it when a result cannot be guaranteed). One photo = one page, a TIFF keeps all its pages. Every image page is shown as wide as an A4 sheet turned the same way, 21 cm for a portrait or square image and 29.7 cm for a landscape one (Michael 2026-10-27: "marche autant sur portrait que paysage"), as tall as the image's proportions (dot shape included: a 204 x 98 dpi fax is not squashed), whatever its resolution or the other files (Michael 2026-10-25): only the page size changes, never a pixel; PDF pages keep their own size. A refused file = no PDF at all, the message names it; unwritable folder = refusal. HDR and depth maps of iPhone photos are dropped silently (Michael 2026-10-24). Dates: creation = oldest of Finder creation, photo capture date (EXIF DateTimeOriginal with its offset) and PDF internal CreationDate; modification = oldest of Finder modification and PDF internal ModDate (read by exiftool); PDF dates before 1993 and capture dates before 1900 are software defaults and ignored; both written on the file (JXA, modification first) and in the PDF /Info, Finder dates read back with an alert. Self-test `services/test-creer-pdf.sh` targets the Mac and uses Michael's real sideways iPhone photo `test-HEIC/img.heic` (Michael 2026-10-27; a HEIC made by sips may already be upright, so it proved nothing): keep that file; under Linux a creation date cannot be set, so its creation-date line and the "aucune alerte" lines fail there by nature. `maj` reruns it when qpdf, img2pdf, exiftool, mozjpeg or any formula they load at run time changes (`brew deps --installed --union`, which brings python, pillow, jpeg-turbo, libtiff and the rest; never ask Pillow, whose `features.version` gives the jpeg version it was compiled with), or the macOS build, the action, the test or its photo (stamp `~/Library/Application Support/maj/creer-pdf.stamp`, written after a clean pass), with a notification on failure.
- Test `Créer un PDF` in the VM with qpdf 12.4.2 built from source (`cmake -DBUILD_SHARED_LIBS=OFF -DREQUIRE_CRYPTO_GNUTLS=1 -DUSE_IMPLICIT_CRYPTO=0`, target `qpdf`), never apt's 11.3: 11.3 words its warnings differently and never reads the unused empty slots of a macOS PDF (qpdf 12 reads them all when the page size sits on the page tree), so a fix proven on 11.3 failed on the Mac (2026-10-26).
- img2pdf's Python carries the pikepdf its Homebrew bottle pinned (10.0.0 from 2025-11, 10.5.1 from 2026-04, 10.16.0 from 2026-10), and Michael's Mac may lag behind: `Créer un PDF` and its self-test use only pikepdf calls present since 10.0, never `Page.get_images` (added in 10.9: every image was refused on the Mac run of 2026-10-24, reproduced in the VM with 10.5.1, the version the Mac showed on 2026-10-25). The self-test prints the versions on its first line.
- Homebrew's img2pdf moved to python@3.15 with pikepdf 10.16.0 (formula read 2026-10-26): the action and its self-test give the same results in the VM under Python 3.15.1 + pikepdf 10.16.0 + Pillow 13.0.0 as under the Mac's 3.14 + 10.5.1 (uv venv with those pinned versions). In the VM, mozjpeg 4.1.5 built from source (`cmake -DPNG_SUPPORTED=OFF -DENABLE_SHARED=OFF`, target `cjpeg-static`, needs nasm) goes to `/opt/homebrew/opt/mozjpeg/bin/cjpeg`, and `/opt/homebrew/bin/exiftool` must be a wrapper script, never a symlink to `~/.local/bin/exiftool`: the symlink loads Debian's 12.57 library, exiftool fails, and the action then shows its unreadable-dates alert.
- Size of a HEIC page (measured 2026-10-27 on Michael's 12 Mpx iPhone photo, 2.1 Mo HEIC with 4:2:0 chroma, PSNR against the decoded photo): JPEG q98 4:4:4 = 6.1 Mo (51.6 dB, the action until 2026-10-27), q98 4:2:0 = 5.7 Mo, q96 4:2:0 = 4.8 Mo (47.4 dB, the action on 2026-10-27 before mozjpeg), q95 = 4.6 Mo (46.4 dB), q92 = 3.6 Mo (43.9 dB), q90 = 3.3 Mo (42.8 dB); matching the HEIC's size needs about q78, below the 40 dB guard. Pillow's JPEG 2000 is worse than JPEG at every size. A PDF cannot hold HEVC, so no lossless or near-lossless way reaches the HEIC's size.
- VM bench imitating the Mac for `Créer un PDF` (and any script run in img2pdf's Python), all outside /work: qpdf and mozjpeg built as above; uv (in a venv) installs Python 3.14 with `UV_PYTHON_INSTALL_DIR=/opt/uvpy`, then `/opt/venv14` holds img2pdf 0.6.3, pikepdf 10.5.1, Pillow 13.0.0 and pillow-heif, and `/opt/homebrew/bin/img2pdf` is a copy of its img2pdf with line 1 `#!/opt/venv14/bin/python` (swap that line to `/opt/venv15/bin/python`, Python 3.15 + pikepdf 10.16.0, to test the next Homebrew); stand-ins: `/usr/bin/sips` (pillow_heif + `exif_transpose`, keeps the ICC profile), `/usr/bin/plutil` (only `-extract KEY raw -o OUT FILE`, via plistlib), `/usr/bin/osascript` (sets only the modification date of a JXA date call, exits 1 otherwise), and `/System/Library/ColorSync/Profiles/Display P3.icc` taken from `test-HEIC/img.heic`.
- Double-clicking a `.workflow` in Finder installs it by moving it into `~/Library/Services` (Michael 2026-10-20): the folder vanishes from scripts and a symlink install becomes a frozen copy. Never double-click one; if it happened, `git restore` the workflow and run `bash services/sync.sh`.
- `services/` holds every Finder Quick Action of Michael's (his choice 2026-10-20): `scripts/services` is the only source, he no longer edits actions in Automator, and nothing in this folder carries a `# menu:` header so the launcher never lists it. `services/sync.sh`, run by `maj` on every pass, links each `services/*.workflow` into `~/Library/Services` under the same name, so edits apply at once with no reinstall; it drops links into scripts whose target is gone and any real copy whose every file git already holds (the old copy of a renamed action included), and reports a same-name real copy that git does not hold. After an `Info.plist` edit (menu name, file types) or a moved scripts folder, run it again. The three `Claude - ask/codeHere/send` actions belong to the Claude app and stay out.

Never install ocrswap's own published Finder action: it would add a second OCR entry, which `sync.sh` does not see.
